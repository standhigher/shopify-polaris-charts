# v1.0 performance budget

The v1.0 release gate runs `npm run benchmark:analytics` against a deterministic
JSDOM workload containing 5, 10, and 20 charts with 100, 500, and 1,000 points.
Every matrix cell measures initial render, one immutable data update, and heap
growth. The command exits non-zero when a cell or bundle measurement is missing,
non-finite, or over budget.

## Release thresholds

| Measurement | Budget |
| --- | ---: |
| `dist/index.js` + `dist/formatters.js`, raw | 100 KiB |
| `dist/index.js` + `dist/formatters.js`, gzip | 18 KiB |
| Initial render, every matrix cell | 2,500 ms |
| Immutable update, every matrix cell | 2,500 ms |
| Heap delta, every matrix cell | 256 MiB |

Bundle accounting adds each public entry's raw and independently gzipped size.
These intentionally broad ceilings detect order-of-magnitude regressions across
developer machines and CI; they are not product latency targets.

## Recorded verification

Recorded on 2026-08-19 using macOS, Node.js v22.17.1, and the repository lockfile.
Two consecutive runs passed all nine matrix cells:

| Run | Bundle raw | Bundle gzip | Slowest initial render | Slowest update | Largest heap delta |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 90,009 B | 15,420 B | 290.28 ms | 358.36 ms | 166,510,384 B |
| 2 | 90,009 B | 15,420 B | 293.76 ms | 339.80 ms | 172,433,800 B |

## Interpretation limits

JSDOM does not reproduce browser layout, painting, compositing, GPU work, or real
ResizeObserver scheduling. This benchmark protects package size, repeated React
work, and major memory/timing regressions only. The Playwright browser matrix is
the release gate for responsive overflow, keyboard interaction, reduced motion,
and real browser compatibility.
