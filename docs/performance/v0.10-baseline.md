# v0.10 Analytics performance baseline

This document records a reproducible development baseline for the v0.10 analytics components. It is not a production browser budget or a release threshold.

## Environment

- Date: 2026-08-19
- Node.js: 22.17.1 with `--expose-gc`
- Platform: macOS (`darwin`)
- Renderer: React DOM in JSDOM with fixed 640 × 240 chart containers
- Workload: alternating `ComparisonChart` and `ConversionChart` instances
- Data: deterministic prepared series with 100, 500, or 1000 time points

Run the benchmark with:

```bash
npm run benchmark:analytics
```

The command builds the package, renders every matrix cell, performs one immutable data update, measures the built ESM bundle, and prints JSON followed by Markdown.

- Raw: 80,665 bytes

Two consecutive runs completed all nine cells with the same workload and output schema. Timing varied as expected; bundle measurements were identical. The largest workload completed without an execution error.

## Interpretation and limitations

- Increasing chart and point counts generally increases update time and retained heap, which makes this matrix useful for spotting large regressions between releases.
- Small workloads are sensitive to JIT warm-up, garbage collection, and scheduler noise. Do not compare individual cells as strict rankings.
- JSDOM does not measure layout, paint, SVG rasterization, browser memory, interaction latency, or Shopify Admin iframe behavior.
- The heap value is the largest observed increase after initial render or update relative to a pre-render forced-GC sample. It is a trend indicator, not a leak diagnosis.
- Browser benchmarks, SSR/hydration measurements, supported-browser coverage, and hard performance thresholds remain v1.0 work.
